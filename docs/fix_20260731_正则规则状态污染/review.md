## 实现审查

- 状态污染发生在调用方正则对象本身；修复在其进入 `.test()` 前隔离实例，处理的是根因，
  而不是在某次判定后补写 `lastIndex = 0`。
- 副本保留原正则的 `source` 和完整 `flags`，仅丢弃跨请求共享的匹配游标。
- 只对 `global` 或 `sticky` 正则创建副本；普通正则继续复用，避免无必要的每请求分配。
- 不使用 WeakMap 缓存副本，避免重新引入一个需要维护游标或生命周期的共享正则对象。
- `matchesUrl()` 仍对直接 RegExp 使用完整 URL；字符串模式仍按现有规则选择 pathname 或
  完整 URL。

## 安全与性能

- 危险规则不会再在第二次命中时降级；安全判定保持确定性。
- 每次命中 `g`/`y` 规则时增加一次 RegExp 构造，复杂度仍与原匹配相同；规则数量通常很
  小，该成本低于引入缓存与状态管理的复杂度。
- 不涉及权限模型、网络请求内容、数据库或外部 API。

## Scope 控制

- 未改变调用方正则 flags 或 JavaScript 匹配语义。
- 未处理跨 realm RegExp、规则预编译或规则格式校验。
- 未夹带其他已知问题修复。

## 自审结论

实现与设计一致，状态型正则的共享游标被限制在一次判定内部；新增测试先稳定复现
间歇性降级和对象状态修改，再验证修复后的确定性。
