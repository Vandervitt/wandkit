# 根目录 README 设计

## 目标

在仓库根目录新建 `README.md`，作为 Wandkit 的 GitHub 项目首页和开发者入口。README 需要让新访问者快速理解项目用途、核心能力、仓库结构和验证方式，并将详细设计与测试记录链接到 `docs/` 中的现有文档。

## 面向读者

- 首次了解 Wandkit 的开发者。
- 需要在本地安装、构建、测试或运行网页 Agent 评估的贡献者。
- 需要了解当前网页任务完成率基线的项目维护者。

## 内容结构

README 按以下顺序组织：

1. 项目名称与一句话定位。
2. 核心能力：Agent Runtime、页面执行、请求拦截治理、聊天 UI 与评估基础设施。
3. 快速开始：环境要求、依赖安装、验证命令。
4. Monorepo 包与主要目录索引。
5. 网页任务完成率基线：10 类任务、确定性评估命令、真实模型评估命令和 GLM-5.2 当前 `27/30（90%）` 结果。
6. 常用脚本表格：测试、类型检查、构建和评估。
7. 详细文档链接，将长篇设计、计划和测试结果留在 `docs/` 中。

## 信息来源

- 包名、脚本和 Node.js 版本要求以根目录 `package.json` 为准。
- 网页任务场景以 `evals/page-agent/scenarios.ts` 为准。
- 通过条件以 `evals/page-agent/site/scenarioRegistry.ts` 为准。
- GLM-5.2 基线数据以 `docs/test_20260802_网页任务完成率基线/test-results.md` 中的已验证记录为准。

## 边界

- README 不声称尚未实现的 `PageAgentRuntime` 或一站式 `WandkitAgent` 已经可用。
- 不暴露真实模型评估使用的 API key、内部端点或本地敏感配置。
- 不在 README 复制详细测试报告，只展示已核实的摘要并链接事实源。
- 不修改业务代码、公开 API 或依赖。

## 验收标准

- 根目录存在 `README.md`，Markdown 结构清晰，仓库内相对链接可解析。
- 安装和常用命令与 `package.json` 一致。
- 基线数据与已验证测试记录一致，明确标注模型、样本量、成功率和已知失败项。
- README 对现有能力与规划中能力的表述没有混淆。
- 文档改动不影响 `npm run verify` 的现有验证结果。
